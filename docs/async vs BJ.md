

## 📌 خلاصه مفهومی Async/Await در برابر Background Jobs (Queues)

هر دو ابزار برای جلوگیری از معطل شدن کاربر استفاده می‌شوند، اما **محل اجرا و پایداری آن‌ها کاملاً متفاوت است.**

---

### 1️⃣ پردازش ناهمگام در حافظه (Async / Await - In-Memory)

* **مفهوم:** کارهای ناهمگام داخل **همان پروسه جاری وب‌سرور** روی Event Loop یا Thread Pool اجرا می‌شوند.
* **پایایی (Persistence):** **ندارد (صفر)!** اگر سرور خاموش یا کرش کند، دیتا در RAM می‌پرد.
* **وابستگی:** کاربر منتظر نتیجه نهایی این پردازش می‌ماند تا پاسخ HTTP را دریافت کند.
* ✅ **کجا استفاده کنیم؟** وقتی کاربر همین الان به نتیجه نیاز دارد و می‌خواهیم چند کار سریع (مثل ۳ کوئری یا API) را **همزمان/موازی** صدا بزنیم.
* ❌ **کجا استفاده نکنیم؟** کارهای سنگین (مثل ساخت PDF یا ویدیو) یا ارسال ایمیل.

---

### 2️⃣ کارهای پس‌زمینه و صف‌ها (Background Jobs / Queues - Out-of-Process)

* **مفهوم:** درخواست وب‌سرور یک «پیام» به Message Broker (مثل Redis یا RabbitMQ) می‌فرستد و **بلافاصله کاربر را آزاد می‌کند**. یک پروسه مجزا به نام **Worker** در پس‌زمینه کار را برداشته و انجام می‌دهد.
* **پایایی (Persistence):** **بسیار بالا!** پیام‌ها روی دیسک/Redis ذخیره می‌شوند. اگر سرور کرش کند، بعد از روشن شدن مجدد، کار از صف برداشته می‌شود.
* **ویژگی کلیدی:** قابلیت **تلاش مجدد (Retry)** خودکار در صورت وقوع خطا.
* ✅ **کجا استفاده کنیم؟** کارهای زمان‌بر (ساخت گزارش Excel)، ارتباطات بیرون از سایت (ارسال ایمیل/پیامک)، و کارهایی که کاربر نباید معطل آن‌ها بماند.
* ❌ **کجا استفاده نکنیم؟** وقتی کاربر خروجی آن کار را برای همان پاسخِ لحظه‌ای (HTTP Response) نیاز دارد.

---

## 💡 جدول مقایسه در یک نگاه:

| ویژگی | Async / Await | Background Jobs (Queues) |
| --- | --- | --- |
| **محل اجرا** | داخل پروسه وب‌سرور (In-Process) | پروسه مجزای Worker (Out-of-Process) |
| **انتظار کاربر** | کاربر منتظر نتیجه می‌ماند | **صفر** (پاسخ بلافاصله صادر می‌شود) |
| **امنیت در کرش** | دیتا پاک می‌شود (RAM) | **ذخیره در صف و قابل بازیابی** |
| **مثال کاربردی** | فراخوانی همزمان چند API | ارسال ایمیل خوش‌آمدگویی / رندر ویدیو |
