
📌 خلاصه مفهومی Rate Limiting (محدودسازی نرخ درخواست‌ها)
⚬ تعریف: تکنیکی امنیتی و معماری برای محدود کردن تعداد درخواست‌های مجاز یک کاربر یا IP در یک بازه زمانی مشخص.
⚬ چرا نیاز داریم؟ 1. جلوگیری از حملات DDoS و Brute Force (تست زدن پسورد یا ارسال کد SMS). 2. جلوگیری از بلعیده شدن منابع RAM/CPU توسط ربات‌ها و اسکرپرها. 3. ارائه پلن‌های تجاری (SaaS) بر اساس میزان مصرف کاربر.
📐 الگوریتم‌های اصلی
1. Token Bucket (سطل توکن - رایج‌ترین): توکن‌ها با سرعت ثابت می‌ریزند؛ هر درخواست یک توکن می‌برد. (اجازه ترافیک‌های لحظه‌ای ناگهانی/Burst را می‌دهد).
2. Leaky Bucket (سطل سوراخ): درخواست‌ها وارد سطل شده و با سرعت یکنواخت خارج می‌شوند. (ترافیک را کاملاً صاف و یکنواخت می‌کند).
3. Fixed Window (پنجره ثابت): بازه‌های زمانی ثابت (مثلاً ۱ دقیقه)؛ (ضعف: احتمال هجوم ترافیک در مرز دو دقیقه).
4. Sliding Window (پنجره لغزان): محاسبه دقیق ۶۰ ثانیه گذشته از همان لحظه درخواست. (دقیق‌ترین روش).
🛠️ هدرهای پاسخ HTTP و کد وضعیت
⚬ کد وضعیت هنگام عبور از حد مجاز: 429 Too Many Requests
⚬ هدرهای مهم پاسخ: ⚬ X-RateLimit-Limit: سقف کل درخواست‌های مجاز. ⚬ X-RateLimit-Remaining: تعداد درخواست‌های باقی‌مانده. ⚬ Retry-After: زمان (به ثانیه) که کاربر باید قبل از ارسال درخواست بعدی صبر کند.
💡 نکات کلیدی بک‌اند:
⚬ محل ذخیره‌سازی: شمارنده‌های Rate Limit معمولاً در Redis ذخیره می‌شوند تا سرعت بررسی آن‌ها در رم فوق‌العاده بالا باشد.
⚬ کجا حتماً بگذاریم؟ اندپوینت‌های لاگین، ثبت‌نام، بازیابی پسورد، ارسال SMS و APIهای عمومی.
اگر نوتت را کپی کردی، بگو تا رسماً وارد مرحله ۵: معماری و دیزاین پترن‌ها (اصول SOLID) بشویم.
