# MVC : Model, View, Controller

## M: Model
-   **Data Access & Business Logic**
-   **Raw Logics and Actions**
-   **مدل** مسئول مدیریت **داده‌ها** و منطق تجاری برنامه است.
-   این بخش مسئول برقراری ارتباط با پایگاه داده، انجام عملیات CRUD (ایجاد، خواندن، به‌روزرسانی، حذف) و اعمال قوانین کسب و کار (Business Rules) است.
-   به بیان ساده، مدل “مغز” برنامه است که تصمیم می‌گیرد داده‌ها چگونه ذخیره، پردازش و بازیابی شوند.

## V: View

-   **ویو** (نما) مسئول **نمایش داده‌ها** به کاربر است.
-   این بخش شامل فایل‌های HTML، CSS و جاوا اسکریپت است که رابط کاربری برنامه را تشکیل می‌دهند.
-   ویو وظیفه پردازش داده را ندارد، بلکه فقط آن‌ها را به شکلی که برای کاربر قابل فهم باشد، نمایش می‌دهد.
-   **نکته مهم:** در یک برنامه MVC استاندارد، ویو نباید منطق تجاری داشته باشد و مستقیماً با پایگاه داده تعامل نمی‌کند.

## C: Controller
API : Req/Res
validations, Error handling / Api Response / file handling / etc
-   **کنترلر** به عنوان **واسط** بین مدل و ویو عمل می‌کند.
-   هنگامی که کاربر درخواستی ارسال می‌کند (مثلاً یک فرم را پر می‌کند)، کنترلر این درخواست را دریافت می‌کند.
-   سپس کنترلر بسته به نیاز، با مدل ارتباط برقرار کرده، داده‌ها را از مدل دریافت می‌کند و یا به مدل دستور می‌دهد تا داده‌ای را ذخیره کند.
-   در نهایت، کنترلر تصمیم می‌گیرد کدام ویو باید نمایش داده شود و داده‌های پردازش شده را به ویو ارسال می‌کند.

# MVC در PHP Laravel
۱. Model (مدل) - «مغز و داده‌های برنامه»
وظیفه: مدیریت داده‌ها، قوانین کسب‌وکار (Business Logic) و ارتباط مستقیم با پایگاه‌داده (Database).

مسئولیت‌ها:

دریافت داده‌ها از دیتابیس یا ذخیره در آن.

اعمال قوانین (مثلاً: قیمت محصول نباید منفی باشد، یا کاربر باید بالای ۱۸ سال باشد).

در لاراول: کلاس‌های Eloquent Model (مثل User.php یا Product.php).

۲. View (ویو) - «ظاهر و رابط کاربری»
وظیفه: ارائه و نمایش داده‌ها به کاربر به شکل قابل فهم (HTML، CSS، JSON یا گرافیک).

مسئولیت‌ها:

ویو هیچ تصمیم منطقی عمیقی نمی‌گیرد و مستقیماً با دیتابیس صحبت نمی‌کند. فقط داده‌هایی که کنترلر به آن داده را نمایش می‌دهد.

در لاراول: فایل‌های Blade (مثل profile.blade.php) یا پاسخ‌های JSON که برای React/Vue فرستاده می‌شوند.

۳. Controller (کنترلر) - «مدیر و هماهنگ‌کننده»
وظیفه: دریافت درخواست کاربر (Request)، صدا زدن مدل برای پردازش/دریافت داده، و تحویل نتیجه به ویو برای نمایش.

مسئولیت‌ها:

کنترلر منطق اصلی داده‌ها را انجام نمی‌دهد؛ فقط به عنوان «واسط» دستور می‌دهد: «ای مدل! داده‌های این کاربر را بده» و سپس «ای ویو! این داده‌ها را بگیر و به کاربر نشان بده».

در لاراول: کلاس‌های Controller (مثل UserController.php).
