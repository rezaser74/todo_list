## 📌 خلاصه مفهومی Async/Await و Non-Blocking I/O

در مدل سنتی (**Blocking**)، تا زمانی که دیتابیس یا شبکه جواب دهد، نخِ اجرا (Thread) به حالت معلق در می‌آید و رم و سی‌پی‌یو تلف می‌شوند.

در مدل ناهمگام (**Non-Blocking**)، سیستم‌عامل کارِ سنگین ورودی/خروجی (I/O) را به عهده می‌گیرد و Thread اصلی آزاد می‌شود تا بلافاصله به درخواست بقیه کاربران پاسخ دهد.

---

## 📐 دیاگرام مقایسه‌ای (Visual Diagram)

### ۱. مدل همگام / مسدودکننده (Synchronous / Blocking):

```text
[ کاربر ۱ ] ──> (درخواست) ──> [ Thread 1 ] ───> [ کوئری دیتابیس ] ──┐
                                                 (منتظر پاسخ...)  │ ۵۰ میلی‌ثانیه
[ کاربر ۲ ] ──> (معطل/صف) ───────────────────────────────────────┼──> (پاسخ به کاربر ۱)
                                                                 │
                               [ Thread 1 ] <─── (دریافت دیتا) ──┘
                                    │
                                    └───> (حالا پاسخ به کاربر ۲)

```

---

### ۲. مدل ناهمگام / غیرمسدودکننده (Asynchronous / Non-Blocking):

```text
[ کاربر ۱ ] ──> (درخواست) ──> [ Thread 1 ] ───> [ ثبت کوئری در Event Loop ]
                                    │
[ کاربر ۲ ] ──> (درخواست) ──> [ Thread 1 ] ───> [ پردازش بلافاصله کاربر ۲! ]
                                    │
                              (خبری از دیتابیس رسید)
                                    │
[ کاربر ۱ ] <── (پاسخ) ─────── [ Thread 1 ]

```

---

## 💡 نکته کنکوری بک‌اند:

> **`Async/Await` معجزه نمی‌کند!** برای کارهای **I/O-Bound** (مثل دیتابیس، API و فایل) فوق‌العاده است، اما برای کارهای **CPU-Bound** (مثل پردازش سنگین ریاضی یا تصویر) تاثیری ندارد و Thread را قفل می‌کند.
